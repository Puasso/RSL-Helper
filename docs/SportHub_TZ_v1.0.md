# Техническое задание (ТЗ) на разработку мобильного приложения «SportHub»

- **Версия:** 1.0  
- **Дата:** 21.01.2026  
- **Цель:** Создать комплексное мобильное приложение для фитнес-клуба, объединяющее тренировки, питание, бронирование и комьюнити.

---

## 1) Бизнес-требования (High-Level Requirements)

Приложение должно решать следующие задачи:

1. **Управление клиентским опытом:**
   - Онлайн-запись на тренировки.
   - Отслеживание активности клиента.

2. **Монетизация:**
   - Продажа подписок на тренировочные программы.
   - Прием онлайн-платежей.

3. **Вовлечение:**
   - Создание сообщества через чаты.
   - Публикация образовательного контента.

4. **Персонализация:**
   - Индивидуальные программы тренировок.
   - Персональные слоты с тренером.

---

## 2) Функциональные требования (Functional Requirements)

## Модуль A: Сообщество и коммуникация (Chat & Feed)

### A.1. Чат («Болталка»)

- Групповые и персональные чаты.
- Отправка текстовых сообщений.
- Отправка фото и видео.
- Поддержка смайлов/эмодзи (стандартная клавиатура + пользовательский набор).

**Рекомендации:**
- Модерация контента.
- Закрепление важных сообщений от тренеров.

### A.2. Лента видео-контента

- Отдельный раздел **«Образование»** с видео о питании и кухонными лайфхаками.
- Воспроизведение видео в ленте:
  - прямая загрузка;
  - или интеграция с YouTube/Vimeo.
- Реакции и взаимодействие:
  - лайки;
  - комментарии;
  - добавление в избранное.

## Модуль B: Тренировки (Workouts)

### B.1. Библиотека тренировочных программ

- Каталог программ с фильтрами:
  - цель;
  - уровень сложности;
  - длительность.
- Детальная карточка программы:
  - описание;
  - цели;
  - расписание.

### B.2. Детализация упражнений

- Возможность открыть каждое упражнение внутри программы.
- Экран упражнения содержит:
  - название;
  - описание техники;
  - видео-демонстрацию;
  - целевые мышцы;
  - рекомендуемое оборудование.

### B.3. Система бронирования (Расписание)

#### B.3.1. Групповые занятия

Календарь с доступными слотами. Слот включает:

- название занятия;
- время;
- дату;
- название клуба;
- номер зала;
- имя тренера;
- уровень сложности;
- количество свободных мест.

#### B.3.2. Персональные тренировки (ПТ)

- Клиент выбирает свободный слот тренера.
- До подтверждения бронирования обязательно заполнение формы:
  - «Цель на тренировку»;
  - «Текущее самочувствие»;
  - «Предыдущие травмы/ограничения (анамнез)».
- Данные формы привязываются к бронированию и доступны тренеру.

### B.4. Личный кабинет клиента

- Раздел **«Мои тренировки»**:
  - список предстоящих занятий (групповых и ПТ);
  - возможность отмены.
- Счетчик тренировок:
  - количество оставшихся занятий по абонементу;
  - дата окончания срока действия («сгорания»);
  - визуальное предупреждение при приближении дедлайна.

## Модуль C: Питание (Nutrition)

### C.1. Раздел «Питание»

- Структурированная библиотека:
  - статьи;
  - рецепты;
  - советы экспертов.
- Интеграция с видео-лентой из модуля A.2.

**Рекомендация (Фаза 2):**
- Личный дневник питания с базой продуктов.

## Модуль D: Коммерция (Payments & Subscriptions)

### D.1. Система подписок

- Каталог платных программ тренировок и/или платных функций (например, «Премиум-питание»).
- Экран тарифа:
  - описание;
  - список преимуществ;
  - кнопка покупки.

### D.2. Прием платежей

- Интеграция с платежным шлюзом (например, CloudPayments, YooKassa).
- Поддерживаемые методы оплаты:
  1. Банковские карты (Visa, Mastercard, МИР):
     - ввод данных карты;
     - или оплата сохраненной картой (токен).
  2. СБП (Система быстрых платежей):
     - оплата по номеру телефона через банк-партнер.

**Безопасность:**
- Соответствие платежных операций стандарту PCI DSS.
- Данные карт не хранятся на серверах SportHub.
- Используются токены платежного провайдера.

## Модуль E: Системные функции (Core)

### E.1. Push-уведомления

- Напоминание о тренировке за 1–2 часа.
- Подтверждение/отмена бронирования.
- Уведомление о списании платежа и успешной покупке.
- Уведомления о новых сообщениях в чате (с настройками).
- Предупреждение о скором истечении пакета тренировок.

### E.2. Профиль пользователя

- Регистрация/авторизация:
  - по номеру телефона;
  - по email.
- Профиль:
  - личные данные;
  - фото;
  - привязанная карта для платежей (через токены провайдера).

## 3) Нефункциональные требования (Non-Functional Requirements)

1. **Платформы:**
   - iOS 14.0+;
   - Android 8.0+;
   - предпочтительно кроссплатформенно (React Native/Flutter).

2. **Производительность:**
   - запуск приложения: не более 2 секунд;
   - загрузка списка тренировок: не более 1 секунды.

3. **Безопасность:**
   - HTTPS для всего трафика;
   - OAuth 2.0 для авторизации;
   - хранение чувствительных данных в Secure Storage.

4. **Масштабируемость:**
   - backend-архитектура должна позволять добавлять новые типы контента и платежные методы.

5. **Нагрузка:**
   - до 10 000 активных пользователей в час.

---

## 4) Приоритизация и план релизов

### Фаза 1 (MVP, 3–4 месяца)

- Базовая авторизация и профиль.
- Модуль бронирования (B.3) + уведомления (E.1).
- Простая библиотека программ (B.1, B.2) без подписок.
- Интеграция платежей (D.2) для оплаты разовых занятий.
- Базовый чат (A.1) без медиа.

### Фаза 2 (Рост, 2–3 месяца)

- Система подписок (D.1) и полный доступ к программам.
- Чат с фото/видео и расширенными эмодзи.
- Раздел «Питание» (C.1) и видео-лента (A.2).
- Счетчик тренировок (B.4).

### Фаза 3 (Оптимизация)

- Расширенная форма анамнеза для ПТ.
- Оффлайн-режим для просмотра программ.
- Умные рекомендации тренировок.

---

## 5) Критерии приемки MVP (Definition of Done)

MVP считается принятым, если:

1. Пользователь может зарегистрироваться/войти и отредактировать профиль.
2. Пользователь может просматривать расписание, бронировать и отменять тренировку.
3. Пользователь получает push-уведомления о тренировках и изменениях бронирования.
4. Пользователь может открыть каталог программ и карточку упражнений.
5. Пользователь может оплатить разовое занятие через подключенный провайдер.
6. Пользователь может обмениваться текстовыми сообщениями в базовом чате.
